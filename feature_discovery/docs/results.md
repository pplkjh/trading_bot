- **후보 종목 행 수**: 많을수록 통계적으로 신뢰도 높음. 100K 이상이면 ML 분석에 충분
- **라벨 유효**: 전체 - 최근 N일 이내 데이터(미래 가격 없음) 제외한 수
- **종목 수**: 1,800개 수준이면 전체 상장 종목의 약 70~80%

### 데이터셋 준비 요약

```
  데이터셋: 398,450 샘플 / 27 피처 / target=fwd_return_10d(binary)
  양성 비율: 52.3%  (208,390/398,450)
```

- **양성 비율 ~50%**: 정상. 10일 후 올랐다/내렸다가 약 반반
- **양성 비율 >> 60%**: 강세장 구간만 포함됐거나 라벨 계산 오류
- **누락 피처**: `supply` 그룹이 많이 누락된다면 backfill 미실행 상태

**feature_discovery 해석 기준** (ml_analysis와 다름)

| r 절댓값 | 등급 | 의미 |
|---|---|---|

| 0.05~0.10 | ★★ 유의미 | 실질적 예측력 존재. sim=7 후보로 충분 |
| 0.02~0.05 | ★ 약한 신호 | 다른 피처와 조합 시 유효할 수 있음 |
| 0.02 미만 | 미미 | 무작위 수준. 단독으로는 무의미 |

| AUC | feature_discovery에서의 의미 |
|---|---|
| 0.50 | 무작위. 이 피처 조합으로는 예측 불가 |
| 0.52~0.54 | 약한 신호. 단독으로는 불충분하나 조합 가능 |

| 0.62 이상 | 매우 강한 신호 또는 데이터 누수 확인 필요 |

> 전체 주식에서 AUC 0.55는 사실상 매우 좋은 수치다.  
> ml_analysis의 AUC 0.58과 단순 비교하지 말 것. 분모(데이터)가 다름.

## 2. 차트 읽기

### `corr_h10_win_all.png` — Pearson r 막대

ml_analysis와 동일한 구조이지만 해석 기준이 다르다.

```
초록 막대 + 길수록:  이 피처가 높은 날 → 10일 후 상승 가능성 높음
빨간 막대 + 길수록:  이 피처가 높은 날 → 10일 후 상승 가능성 낮음 (역상관)
```

**주목할 패턴들:**

```
inst_buy_ratio > 0 (초록, 길수록 좋음)
  → 기관이 순매수한 날 이후 실제로 오름  (score_g 효과 직접 검증)

rsi14 역상관 (빨간)
  → RSI 높은 종목은 이미 많이 올라 추가 상승 제한됨  (알려진 평균회귀 현상)

bb_position 역상관 (빨간)
  → BB 상단에 가까운 종목은 10일 후 추가 상승 제한됨  (Strategy A 입장 vs Strategy B 입장 비교 가능)
```

### `importance_h10_win_all.png` — 피처 중요도

ML 모델이 10일 후 수익을 예측할 때 어떤 피처를 가장 중요하게 봤는가.

```
rsi14가 최상위 → "RSI가 낮을 때 매수 = 이후 상승" 패턴 (비선형 효과)
inst_buy_ratio가 상위 → 독립적 예측력 확인됨
adx가 상위 → 추세 강도 = 주가 상승의 지속성과 연관
```

> 비선형 효과: Pearson r이 낮아도 CatBoost 중요도는 높을 수 있음.  
> `rsi14`가 역상관(-r)이지만 CatBoost에서 중요하다면  
> → "특정 RSI 구간(예: 30~45)에서만 예측력이 있음" → 비선형 패턴

### `importance_cmp_h10_win_all.png` — 모델 간 비교

```
모든 모델에서 높음 → 선형+비선형 모두 강함. sim=7 최우선 후보
CatBoost만 높음   → 비선형 패턴만 있음. 현재 선형 스코어에 추가 어려움
LASSO만 높음      → 선형 관계만. 현재 스코어 구조와 호환됨
모두 낮음         → 이 피처는 10일 후 수익과 관계 없음
```

### `shap_bee_h10_win_all.png` — SHAP Beeswarm

각 점 = 하나의 후보 종목 × 날짜 (trade가 아닌 candidate).

```
inst_buy_ratio  [파란 점들이 왼쪽, 빨간 점들이 오른쪽]
→ 기관 순매수 비율이 높은 날(빨강) → 10일 후 상승 확률 높음 (오른쪽으로 분포)
→ 기관 매도 or 데이터 없음(파랑)  → 10일 후 상승 확률 낮음 (왼쪽으로 분포)

rsi14  [빨간 점들이 왼쪽, 파란 점들이 오른쪽]
→ RSI 높을 때(빨강) → SHAP 값 음수 (win 확률 낮추는 방향)  ← 역U자 비선형 패턴 가능
→ RSI 낮을 때(파랑)  → SHAP 값 양수 (win 확률 높이는 방향)
```

SHAP이 Pearson r의 단순 상관보다 더 세밀한 비선형 패턴을 보여준다.

## 3. 호라이즌별 비교 해석

```bash
python -m feature_discovery.main --cache fd.parquet --horizon 5  --mode corr_only
python -m feature_discovery.main --cache fd.parquet --horizon 10 --mode corr_only
python -m feature_discovery.main --cache fd.parquet --horizon 15 --mode corr_only
```

각 결과의 `correlation_h{N}_win_all.csv`를 비교:

| 패턴 | 해석 |
|---|---|
| 5일 r 높음 > 10일 r | 단기 신호. Strategy A용 (평균 보유 4.6일) |
| 10~15일 r 높음 > 5일 r | 중기 신호. Strategy B용 (평균 보유 10.2일) |
| 모든 호라이즌 r 비슷 | 강건한 신호. 전략 무관하게 유효 |
| 5일 r 양수, 15일 r 음수 | 단기 상승 후 반전. 단기 트레이딩에만 적합 |

## 5. 결과를 sim=7 설계에 활용하는 법

### Step 1: 강력한 피처 후보 선별

다음 조건을 모두 통과하는 피처를 찾는다:

1. feature_discovery `correlation_*.csv`: |r| ≥ 0.05
2. feature_discovery `importance_catboost_*.csv`: 상위 10위
3. feature_discovery `perm_importance_*.csv`: 양수
4. ml_analysis에서도 동일하게 유의미

### Step 2: 호라이즌 매칭

- 5일 신호 강한 피처 → sim=7 Strategy A 컴포넌트 후보
- 10~15일 신호 강한 피처 → sim=7 Strategy B 컴포넌트 후보

### Step 3: 비선형 패턴 확인

Pearson r이 낮지만 CatBoost 중요도가 높은 피처:
- 선형 스코어(0~N점 단조증가)에 넣으면 효과 없음
- 대신 **임계값 기반 이진 조건**으로 설계해야 함
  ```python
  # 예: rsi14 < 40 일 때만 5pt 부여
  score += 5 if row['rsi14'] < 40 else 0
  ```

### Step 4: 새 TR 데이터 우선순위 결정

현재 수집되지 않은 TR 데이터를 추가할 때:  
feature_discovery에서 기존 피처로 달성 가능한 AUC 상한을 먼저 파악 →  
새 TR 추가 후 AUC 상승 폭으로 해당 TR의 가치 정량화.

## 6. 결과 활용 주의사항

1. **r 값이 작아도 실망하지 말 것**  
   전체 주식 우주에서 r = 0.07은 충분히 의미 있는 신호다.

2. **Walk-Forward CV 결과가 안정적인지 확인**  
   fold별 AUC 편차가 크다면 (±0.05 이상) 시장 국면에 따라 신호가 불안정하다는 뜻.

3. **backfill 이전 기간 포함 주의**  
   inst_buy_ratio가 많이 NaN이면 분석 왜곡. `--start`를 backfill 완료 시점 이후로 설정.

4. **캐시는 피처 계산 결과까지 포함**  
   `hybrid_strategy_v3.py` 변경 후에는 캐시 재생성 불필요 (캐시는 raw 피처 기준).  
   `data_builder.py`의 피처 계산 로직 변경 시에는 캐시 삭제 후 재생성 필요.

5. **최종 결정은 백테스트로**  
   feature_discovery 결과는 "어떤 피처가 가능성 있는가"의 답이다.  
   실제 스코어에 반영 여부는 항상 `score_analyze.py` 백테스트로 검증.
